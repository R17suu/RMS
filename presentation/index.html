01 — Introduction

What is the EEU RMS?

A comprehensive mobile application designed to digitize and streamline the retail operations of the Economic Enterprise Unit.

📱 About the Application

The EEU Records Management System (RMS) is a cross-platform mobile application built to manage and automate the daily retail operations of a campus economic enterprise unit — from point-of-sale transactions and inventory tracking to user access control and system monitoring.


The application replaces manual record-keeping with a secure, role-based digital system accessible on any mobile device.

💡 Why Was It Developed?

Campus enterprise units often rely on manual processes for tracking sales, managing inventory, and maintaining records. This leads to:

  • Inaccurate sales records and revenue tracking
  • Difficulty monitoring low-stock items
  • No centralized access control for staff
  • Time-consuming report generation
02 — Problem Statement

The Problem We Solve

📋

Manual Record-Keeping

Sales, inventory, and user records are maintained on paper or spreadsheets, leading to data inconsistencies, loss of records, and difficulty in auditing.

📊

No Real-Time Monitoring

Management has no way to monitor live sales, inventory levels, or system activity without physically checking records at the store.

🔐

No Access Control

All staff have the same level of access to data and operations, creating security risks and accountability issues for sensitive operations.

⏱️

Slow Operations

Manual checkout, stock counting, and report generation consume excessive time that could be spent on more productive tasks.

03 — Objectives

Project Objectives

🎯 General Objective

To develop a mobile-based records management system that digitalizes the retail operations of the Economic Enterprise Unit, providing efficient sales processing, inventory management, and role-based access control.

Specific Objective 1

To implement a Point-of-Sale (POS) module that enables fast and accurate sales transactions with real-time receipt generation.

Specific Objective 2

To develop an inventory management system that tracks stock levels, alerts low-stock items, and manages restocking operations.

Specific Objective 3

To implement a role-based access control system with three user levels (Super Admin, Admin, Clerk) to ensure data security and accountability.

Specific Objective 4

To create a real-time dashboard that displays key metrics such as revenue, sales volume, and system health for informed decision-making.

07 — Development Process

How We Built It

Our development followed an iterative approach through four key stages.

📐 Planning

Requirements gathering, identifying user roles, defining permissions, and planning the database structure and app architecture.

🎨 Design

Creating UI mockups, designing the dark-themed interface, establishing the color scheme, and mapping out the navigation flow.

💻 Development

Building the React Native components, implementing Firebase authentication, integrating Firestore database, and creating the role-based routing system.

🧪 Testing

Testing on multiple devices using Expo Go, verifying role-based access, validating POS transactions, and checking database integrity.

10 — Challenges Encountered

Challenges & Solutions

1

Firebase Authentication Session Conflict

Problem: Creating a new user in Firebase Auth automatically signs out the current admin. Solution: Implemented a secondary Firebase app instance to handle account creation without affecting the admin's active session.

2

Role-Based Permission System Complexity

Problem: Implementing 26 granular permissions across 3 user roles with dynamic tab visibility. Solution: Stored permissions in AsyncStorage after login and conditionally rendered navigation tabs based on the user's assigned permissions.

3

Expo Go Version Compatibility

Problem: The latest Expo SDK 55 was not compatible with the Play Store version of Expo Go. Solution: Used web mode for testing and development builds for device testing.

4

Real-Time Data Synchronization

Problem: Ensuring inventory updates reflect immediately after POS transactions. Solution: Leveraged Firestore's real-time listeners and optimistic UI updates for instant feedback.
